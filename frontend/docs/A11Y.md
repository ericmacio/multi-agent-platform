# Accessibility (A11Y) — v1 baseline

The multi-agent platform targets **WCAG 2.1 AA** per SW-DESIGN §11.6. This
document records the manual audit run for **US-11-006** and the automated
regression net that guards it against drift.

## Automated regression

- Package: `vitest-axe` (see `frontend/package.json` devDependencies).
- Helper: `src/test/axe.ts` exports `expectNoA11yViolations(container)`.
- Two axe rules are disabled by default (see helper source for the why):
  - `color-contrast` — jsdom cannot compute contrast without the `canvas`
    npm package. Contrast is verified manually below.
  - `region` — many primitive-scoped tests render a fragment outside any
    landmark; the shell-level tests cover the landmark rule.
- Assertions are wired into: `Button`, `Input`, `Modal`, `Toast`, and the
  `LoginPage` integration test. New primitives / pages should add an
  `a11y:` test on their representative DOM.

### Focus trap on overlays

- `<Modal>` — traps focus, restores focus to the trigger on close, `Esc`
  closes, `role="dialog" aria-modal="true"`. Confirmed by
  `Modal.test.tsx` (`Tab cycles within the modal`).
- `<Dropdown>` — closes on `Esc`, focus returns to the trigger.

### Visible focus on dark backgrounds

`--color-border-focus: #A78BFA` (violet) is used as a `2 px` outline with a
`2 px` offset (see `tokens.css` and `Button` / `Input` classnames). Spot-
check on `--color-bg-base` (#0F0F14) and `--color-bg-elevated` (#1C1C26):
outline is clearly visible on both.

### `aria-live` regions

Only three regions announce dynamic content:

- `ToastViewport` — `aria-live="polite"` on the fixed toast surface.
- `OfflineBanner` — `role="status" aria-live="polite"` when offline.
- `MessageList` in `ConversationView` — `role="log" aria-live="polite"`;
  incremental `delta` text is NOT announced (would flood the screen
  reader); the completed assistant message is announced on `completed`.

No accidental `aria-live` on decorative regions.

### Color contrast (WCAG AA)

Manual spot-check via the Chrome Lighthouse contrast panel on the three
primary pages. Text ≥ 4.5:1; large text / UI ≥ 3:1.

| Pair                              | Ratio | Pass |
|-----------------------------------|-------|------|
| `text-primary` on `bg-base`       | 15.3  | ✅   |
| `text-primary` on `bg-surface`    | 13.6  | ✅   |
| `text-secondary` on `bg-base`     | 9.4   | ✅   |
| `text-muted` on `bg-base`         | 5.4   | ✅   |
| `text-accent` on `bg-base`        | 6.1   | ✅   |
| `text-danger` on `bg-base`        | 6.6   | ✅   |
| `text-warning` on `bg-base`       | 12.0  | ✅   |

All pass ≥ 4.5:1. The `text-disabled` token is only used on non-interactive
disabled controls where a lower contrast is acceptable.

### Screen-reader labels

- Icon-only buttons carry an `aria-label` (`X`/`MoreHorizontal` dropdown
  triggers, `Dismiss` on toasts, etc.). Verified by
  `AdminApiKeysPage.test.tsx` (`actions for cid-1`).
- The send button on the chat composer has both a visible label AND an
  icon per SW-DESIGN §11.6.

## Follow-ups deferred

- **Screen-reader real-hardware pass** — JAWS / NVDA / VoiceOver testing
  is a QA milestone, not part of this story.
- **`prefers-reduced-motion`** — the animation budget (SW-DESIGN §11.5)
  already caps transitions at 120 ms and forbids per-character streaming
  animation, so the reduced-motion default is close to the full motion.
  A future story may add explicit `@media (prefers-reduced-motion: reduce)`
  rules if user feedback demands them.
- **E2E axe** — Playwright's axe integration is deferred with the rest of
  the E2E layer (SW-DESIGN §17 TBD-F7).
